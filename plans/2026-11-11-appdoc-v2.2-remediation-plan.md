# AppDoc v2.2.0 Remediation Plan

**Date:** 2026-11-11
**Input:** [docs/standard-comparison-2026-11-11.md](../docs/standard-comparison-2026-11-11.md) — cross-cutting findings X1–X16 and per-repo errors from comparing the four regenerated examples against `C:\Github\helpweb\Planning\HELP_DESK_APPLICATION_DOCUMENTATION.html`.
**Previous round:** v2.1.0 (template restructure, Check rule C8, Appendix A rendering) — done.
**Status:** Approved for implementation.

## Goal

Close the remaining gaps between AppDoc output and the standard by changing the **skill** (extractor, template, Check, guidance), so every future document improves — then regenerate the four examples and re-measure.

## New finding from planning

The gitea file-count discrepancy (e.g. `modules/` 1288 on disk vs 1220 in Facts) is an **extractor bug**, not an AI error. `appdoc/scan.py` prunes any folder named `packages` at **any depth** via `ALWAYS_IGNORE_DIRS`, so gitea's entire package registry is missing from the Facts:

- `routers/api/packages/`
- `modules/packages/`
- `services/packages/`
- `models/packages/`

## Decisions

| ID | Decision | Rationale |
|----|----------|-----------|
| D1 | Add two hard-fail Check rules: **C9 Document consistent** and **C10 Evidence Register complete**. | The Check is pass/fail with no warnings; these findings are machine-detectable. |
| D2 | A missing `verification.md` stays a noted gap, not a failure. C10 runs only when the file exists. | Keeps existing tests and policy (ADR 0003 spirit). Revisit after Phase 7. |
| D3 | `packages` is pruned only at the Target root (NuGet). All pruned folders are recorded and listed in `facts-summary.md`. | Fixes the gitea gap without pulling NuGet caches into large .NET Targets. |
| D4 | The source-to-claim audit is run by a fresh agent/context that did not write the document, and covers every section (sampling allowed but stated). | Removes self-grading; addresses partial audits. |
| D5 | One new required subsection: **16.6 Configuration reference**. The data dictionary lives inside 8.4. No renumbering. | Minimal structural change; C3/C4/C2 hard-code current numbering. |
| D6 | Regenerate all four examples and re-run the comparison. | Measures the effect of the change. |

**Out of scope:** Go / OpenAPI / INI / MAUI extractors; a re-run command executor; mechanically checking that a citation *supports* its claim; checking that a section cross-reference is *correct* (C9 checks only that it *exists*).

## Phase 1 — Extractor fix *(parallel with Phase 2)*

**Files:** `appdoc/scan.py`, `appdoc/extract.py`, `appdoc/facts.py`, `appdoc/summary.py`, `tests/test_core.py`

1. `scan.py`
   - Remove `packages` from `ALWAYS_IGNORE_DIRS`; add `ROOT_ONLY_IGNORE_DIRS = {"packages"}`.
   - In `walk()`, prune a root-only name only when `dirpath == root`.
   - Add optional parameter `pruned: list[str] | None`; append each pruned folder's Target-relative path. Sort before returning.
2. `extract.py`
   - Pass a list to `scan.walk()` and store it as `doc["target"]["pruned_folders"]`.
3. `facts.py`
   - Bump `SCHEMA` (minor) because the target metadata shape changes.
4. `summary.py`
   - New section `## Folders not scanned`: one bullet per pruned folder, with the note "These were skipped by name. Read them if they hold source." Write "None." when empty.
   - New section `## Config files`: table `| File | Config keys |` built from `config_key` Facts (non-test), sorted by count desc then path, capped at `FOLDER_CAP`.
5. `tests/test_core.py`
   - Nested `src/packages/x.py` is scanned.
   - Root `packages/x.nupkg` is pruned and appears in `pruned_folders`.
   - `test_ignored_dirs_and_appdocignore` still passes.
   - Summary contains both new sections; empty-list wording test updated.
   - Determinism tests (`test_two_runs_are_byte_identical_for_every_sample`) still pass.

## Phase 3 — Check rules *(depends on Phase 2)*

**Files:** `appdoc/check.py`, `tests/test_check.py`

1. `REQUIRED_SUBSECTIONS["16.6"] = "Configuration reference"`.
2. **C9 Document consistent** — fails when:
   - **(a)** a table data row's cell count differs from its header's. Split on `|` that is not escaped (`\|`) and not inside backticks; ignore rows inside code fences.
   - **(b)** prose refers to `section N`, `section N.M` or `§N.M` and no `## N.` / `### N.M` heading exists. Ignore code fences and HTML comments.
   - **(c)** section 1 does not mention `Appendix A`.
   - **(d)** the raw Markdown still contains a template guidance comment (an HTML comment containing `Fed by:`).
3. **C10 Evidence Register complete** — runs only if `verification.md` exists; fails when:
   - the first table's header is not `ID | Section | Claim | Result | Citation | Re-run | Limitation`;
   - a Result is not `Supported`, `Corrected` or `Downgraded`;
   - an ID repeats;
   - any of sections 2–13, 15, 16 has no row (match on the Section cell's leading number);
   - a 10.1 finding ID (first column of the 10.1 table) or a `### 7.x` workflow number has no row;
   - the line `**Summary:** N rows: S Supported, C Corrected, D Downgraded.` is missing or its numbers don't match the table;
   - the file contains "previous version" or "earlier draft" (case-insensitive).
4. Add `"C9": "Document consistent"`, `"C10": "Evidence Register complete"` to `RULE_TITLES`; update the module docstring to C1–C10. Report ordering must handle `C10` after `C9`.
5. Tests:
   - `build_doc()` emits `### 16.6`, an `Appendix A` mention in section 1, and well-formed tables.
   - One failing test per C9 sub-check (a–d) and per C10 sub-check.
   - Edge cases: pipes in backticks, escaped pipes, tables inside code fences, xrefs inside comments.
   - Existing "verification absent → pass" test still passes; update the "verification present" fixtures to a valid register.
   - `test_template_is_valid_shape` includes 16.6.
